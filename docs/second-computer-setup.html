Bringing a second computer onto the Ollama bridge

Your models stay on this machine. Every other computer reaches them through one gate — ollama.verseviewllm.dpdns.org — that only opens for a matching key. This page walks that key onto a Windows machine and an Intel Mac.

Before you start

Get these from whoever set up the tunnel — the service token is a shared secret and is deliberately not written down on this page.

  • The endpoint address
    https://ollama.verseviewllm.dpdns.org — the same on every computer, never changes.
  • The service token pair
    A CF-Access-Client-Id and CF-Access-Client-Secret — the key itself, as one JSON object.
  • VerseView on that computer
    Installed and able to open Settings.
Treat the token like a password. Anyone holding both header values can call the home Ollama through the tunnel. Send it over something private — never paste it somewhere public.

Same five steps, two platforms

Open VerseView on the remote computer, then follow the column that matches it.

WINDOWS

Any other Windows PC

  1. Open Advanced Settings
    In the Settings panel on the right, scroll to Options → expand it → scroll to Advanced Settings → expand it → scroll to Local LLM (Ollama).
  2. Turn it on
    Check Use Local LLM if it isn't already.
  3. Set the endpoint
    Paste into Local Ollama Endpoint:
    https://ollama.verseviewllm.dpdns.org
  4. Set the key
    Paste your saved token JSON into Extra Headers, shaped like:
    {"CF-Access-Client-Id": "…", "CF-Access-Client-Secret": "…"}
    Leave Auth Token blank.
  5. Test it
    Click Test Connection.
    Local LLM test OK — Connected to https://ollama.verseviewllm.dpdns.org
MAC · INTEL

Intel-based Mac

  1. Skip the .app — launch the raw executable
    The .app is ad-hoc signed but not notarized, so Gatekeeper quarantines and translocates it — that's the crash. The Raw Executable folder in the same release zip is the identical program without that layer. Open Terminal and cd into it, then run it directly:
    cd ~/Downloads/"VerseView-Mac-Intel-Release"/"VerseView Detector (Raw Executable)" ./"VerseView Detector"
    Adjust the first path if you unzipped somewhere other than Downloads. Leave this Terminal window open — closing it quits the app.
  2. Open Advanced Settings
    Same path as Windows — Options → Advanced Settings → Local LLM (Ollama) — the panel is identical on both platforms.
  3. Turn it on and set the endpoint
    Check Use Local LLM, then paste into Local Ollama Endpoint:
    https://ollama.verseviewllm.dpdns.org
  4. Set the key
    Paste the same token JSON into Extra Headers as on Windows — it's the one key, shared by every remote computer. Leave Auth Token blank.
  5. Test it
    Click Test Connection. First reply can take longer while Ollama loads the model into memory on the host.
    Local LLM test OK — Connected to https://ollama.verseviewllm.dpdns.org

If Test Connection doesn't say OK

The gate is doing exactly what it's designed to — these are the two ways it says no.

MessageWhat it meansFix
HTTP 403 — did not authenticate The two header values didn't match what Access expects. Re-copy the JSON exactly — no missing quote, no trailing space, both keys present.
Timed out after 20s Access let it through, but Ollama took a while to answer. Usually just a cold model load on the host. Try Test Connection again — it should be quick the second time.
Mac: .app quits instantly / "damaged" Gatekeeper quarantine on an ad-hoc-signed, unnotarized build. Use the Raw Executable from the same zip (step 1, left), or run xattr -cr on the .app after moving it to /Applications.
